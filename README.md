# AiSlopcraft — reference-led native rebuild (early art study)

An **unofficial, independently implemented** C++20 voxel-sandbox project aiming at the *era* of **Minecraft Java Edition release-numbered 1.7.3 (December 2013)**, the first 1.7.4 pre-release. **Not Beta 1.7.3.** AiSlopcraft is **not affiliated with, sponsored or endorsed by Mojang Studios or Microsoft**. No Mojang game code, JAR, textures, sounds or branding are distributed. Our art and code are original; SDL3 and stb are used under their licences. The superseded prototype's Press Start 2P font is SIL OFL-licensed.

> **Status: IN PROGRESS — restart after a rejected Windows retest.** The user reports the previous native build is still badly unfinished and visually unlike the target. The old `aislopcraft` binary, its history and existing `saves/` remain available for rollback, **not** as an accepted visual foundation. New `aislopcraft-rebuild` is an **isolated, fixed-scene, in-memory creative art study**, not a complete game or a confirmed 1.7.3 likeness. Its appearance, physical Windows mouse response and target-PC FPS are **not VERIFIED**. Follow the [reference-led rebuild plan and acceptance gates](docs/REBUILD_PLAN.md); do not confuse green CI with a visual review. [PR #17](https://github.com/Skid-ster/AiSlopcraft/pull/17) remains open.

## What the *new* path currently does

- Independent `src/rebuild/` world, DDA raycast, collision/movement and chunk-local mesh generation; a **fixed bounded meadow/forest scene**, not Java world generation. Original 16-pixel materials and plants generated by `tools/rebuild_art.py` (Python standard library; no proprietary packs or Pillow). Independent SDL3/OpenGL 3.3 renderer/game loop shares only the minimal platform GL-loader code and the licensed SDL3/stb dependencies with the old executable.
- In-memory creative movement, 4.5-block face selection, left-click break/right-click place, nine-slot hotbar, alpha-cutout foliage, flat day lighting and F2 PNG capture. Changes are **not saved**; closing the study resets it. It never reads or writes `saves/` or `options.txt`.
- Headless tests check deterministic scene, 100 edit/restore cycles, negative-coordinate raycast and reach, adjacent-chunk mesh edits, walk/jump/collision and initial camera target. Linux CI captures before/after a block placement and sends **SDL-synthetic** Escape/recapture/place/mine events through the actual event dispatcher. **File output is not proof of visual similarity or physical Windows input.** A matched reference-client comparison and real Windows input/performance measurements are still missing.
- **Missing from the study:** survival, inventory/crafting, persistent saves, infinite world/lighting/fluids, credible full terrain and biome variety, first-person hand/item, skies/clouds/weather, mobs, 1.7.3-specific UI/texture comparison and the rest of the game. The previous executable has partial implementations of some of these, but its look was rejected and its systems are *not* automatically promoted into the rebuild.

Statuses in the [plan](docs/REBUILD_PLAN.md) and [feature matrix](docs/FEATURE_MATRIX.md) use **NOT STARTED, IN PROGRESS, IMPLEMENTED, VERIFIED, BLOCKED**. VERIFIED is restricted to a particular named test/comparison.

## Build and try the *new study*

### Windows (primary target)

Requires an installed Visual Studio/Build Tools **with MSVC C++ and a Windows SDK** (not specifically VS 2022), CMake ≥3.20, Ninja or NMake, an OpenGL 3.3-capable driver and internet to download pinned SDL3 3.4.18 source. A Git checkout or source ZIP contains `CMakeLists.txt` and `build-windows.cmd`; a prebuilt CI artifact contains binaries/assets but **not** build sources. The helper detects the available MSVC toolchain (including 2022/2026), builds *both* executables and runs the headless CTests/selftests. It does not verify a graphical Windows launch.

From **Command Prompt**, explicitly change to the *source* directory (replace this example path if yours differs):

```cmd
cd /d "C:\path\to\AiSlopcraft-src"
call build-windows.cmd
build\Release\aislopcraft-rebuild.exe
```

To get updated source, use the **current PR branch's Source ZIP** or, *if this directory is already a Git checkout of that same branch*, run `git pull origin arena/433092f5-aislopcraft` before building. Do not run `git pull` in an extracted ZIP. `build\Release\aislopcraft.exe` is the **superseded** prototype and is not the new study. The helper uses `vswhere` plus the installed `VsDevCmd.bat`, then Ninja or NMake, and does not require a VS-year-specific CMake generator. Old `saves/` and `options.txt` remain untouched when running the rebuild; the study currently has **no saves**. Copy the rebuild executable **with** its adjacent `assets/` directory when distributing a test build.

### Linux

A desktop with SDL3 video dependencies (X11/Wayland) and an OpenGL 3.3 driver is needed for the interactive study. CMake fetches pinned SDL3 if unavailable. Ubuntu CI installs X11/Mesa headers and runs Xvfb/Mesa software GL; this local sandbox has no working desktop GL, so local `SDL_UNIX_CONSOLE_BUILD=ON` builds can compile/run headless tests but **not** render. A normal desktop build is:

```bash
cmake -S . -B build/release -DCMAKE_BUILD_TYPE=Release
cmake --build build/release --parallel 4
ctest --test-dir build/release --output-on-failure
./build/release/aislopcraft-rebuild --selftest
./build/release/aislopcraft-rebuild
```

For a core-only build without SDL/GL, configure with `-DVOXCRAFT_BUILD_APP=OFF`, build and run CTest. No macOS support claim.

### Study controls (creative only; physical Windows retest pending)

| Input | Action |
|---|---|
| WASD / mouse / Space / Ctrl | Walk / look / jump / sprint (AABB collision; step-up not implemented) |
| Left click / right click | Break targeted solid block / place selected block against its face, within 4.5 blocks; first click after releasing capture only recaptures |
| 1–9 / mouse wheel | Select original-material hotbar slot |
| Esc / click | Release mouse and pause / click to recapture (without mining on that click) |
| F2 / F3 / F7 | Save own PNG to `screenshots/rebuild/` / diagnostics (FPS, CPU draw/swap, last mesh edit, target, edit count) / cycle integer GUI scale |
| Close window | Discard the study's in-memory edits — no save format yet |

## Validation and visual evidence

- **VERIFIED (build and narrow headless behaviors only):** Local GCC Release core-only CTest passed 3/3; full dummy/no-GL SDL build passed 5/5. [PR CI 41356845709](https://github.com/Skid-ster/AiSlopcraft/actions/runs/41356845709) built both executables on Windows 2022, VS 2026 and Ubuntu, passed all **5/5** CTests and tested the Windows build helper. `rebuild_core_tests` covers the scene/mesh/raycast/controller and 100 direct edit cycles; `rebuild_startup_smoke` checks the initial target. This does not prove a physical Windows game launch.
- **VERIFIED (narrow Linux synthetic GL/SDL integration only):** The Ubuntu Mesa/Xvfb `--smoke <dir>` passed SDL-synthetic Escape/recapture/right-place/left-mine through the same event dispatcher as gameplay and captured distinct 1280×720 `before.png`/`after.png` frames. It checked broad sky/vegetation/HUD pixel classes, not the actual appearance against 2013. Captures were uploaded but cannot be visually inspected from this restricted sandbox. Prior [CI on `1f53fa8`](https://github.com/Skid-ster/AiSlopcraft/actions/runs/41351627299) validated only the **rejected prototype**.
- **BLOCKED:** No lawfully captured, matching 2013 client side-by-side or new Windows screenshot has been reviewed; no measured 2560×1440 frame-time percentiles on the user's i5-13400/RTX 5060 Ti/16 GB PC. The seven-scene reference and performance gates are in [REBUILD_PLAN.md](docs/REBUILD_PLAN.md). Do not claim it looks like 1.7.3 yet.
